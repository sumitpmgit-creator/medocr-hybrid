# qa/: MedOCR Hybrid QA suite

QA for the #BuildHybridAI 2026 entry. QA writes only inside `qa/`. Product code in `packages/core`, `packages/parsing`, `datasets/`, and `apps/web` is read and executed, never edited. Do not commit from here (Advisory commits hourly). `qa/node_modules` is git-ignored.

## Run it

```bash
cd /workspace/med-ocr/qa
pnpm install --ignore-workspace       # once; installs vitest 5.1.1 into qa/node_modules only
pnpm test                             # whole suite (vitest run)
npx vitest run tests/deid.test.ts     # one area: harness | repo | routing | deid | scoring | offline
npx vitest run -t "DEID-E2E"          # by test-ID prefix
pnpm results                          # full run -> results/latest.json + results/SUMMARY.md (per-area counts)
```

No Firebase project, API key, Chrome, or network is needed. Every model call is mocked, and the egress spy blocks real network access by default.

## Layout

| Path | What |
|---|---|
| `TEST_PLAN.md` | Areas, test-case IDs, what each checks and how; manual checks; benchmark plan |
| `BUG_LOG.md` | Reproduced bugs with severity, owner, repro, expected vs actual, status |
| `results/SUMMARY.md` | Latest per-area pass/fail/skip and every failing test (regenerated by `pnpm results`) |
| `tests/*.test.ts` | One file per area |
| `src/core.ts` | Loads `@med-ocr/core` / `@med-ocr/parsing` through their public `exports["."]` (falls back to `src/*.ts` and fails REPO-01 if the entry is broken). `CANDIDATES` maps capabilities to export names |
| `src/egress.ts` | Network-egress spy (fetch, XHR, beacon, WebSocket, node:http(s)); deny / respond / offline modes; `leaks()`, `binaryEgress()`, `totalBytes` |
| `src/pii.ts` | Adversarial synthetic PII corpus (Indian names, phones, Aadhaar/VID/ABHA/PAN, addresses/PIN, DOB, MRN/UHID, email) plus the leak scanner (handles JSON, URL, base64, full-width and Devanagari digits) |
| `src/mocks/nano.ts` | Gemini Nano mock (Chrome Prompt API `LanguageModel`) |
| `src/mocks/firebase-ai-sdk.ts` | `firebase/ai` replacement with @firebase/ai 3.1.0 InferenceMode semantics; cloud calls go through `fetch`, so the spy sees them |
| `src/mocks/web-firebase.ts` | Replacement for `apps/web/src/firebase.ts` (no real app) |
| `src/mocks/stages.ts` | Mock core `Stage`s (Nano OCR, Firebase structure, local, hanging) |
| `src/oracle.ts` | Independent Levenshtein CER/WER, ECE, seeded PRNG, text corrupter |
| `vitest.config.ts` | Resolve plugin that points `firebase/ai` and apps/web's `./firebase` at the mocks during QA runs only |
| `scripts/record-results.mjs` | Writes `results/` |

## How to read the results
- **Failed** means a reproduced defect (see BUG_LOG) or a gate test for a missing capability (e.g. SCORE-42, no calibration export).
- **Skipped** means the code under test isn't exported yet. Those tests turn on by themselves when it lands.
- The suite runs the **real** apps/web Stages (`nanoRead`, `nanoStructure`, `deidStage`, `cloudStructure`, `hybridVerify`) through core's `runPipeline`. Only the model and SDK layer is fake.

## Adding a PII case
Add an entry to `PII_CASES` in `src/pii.ts` with `text`, the `pii` values that must never leave, and the clinical strings to `keep`. It is picked up automatically by HAR-01, by the DEID-{core,parsing}-* tests, and by the over-redaction checks. Use synthetic values only. Never put real patient data in this public repo.
